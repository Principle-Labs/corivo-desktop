01 · The Timeline Decision

删 Timeline。

你的判断是对的——它是个 demo 阶段的"数据库浏览器",看着像功能,实际上是把内部数据层端到了用户面前。删掉它,IA 立刻从两个一级路径塌成一个,产品心智更尖锐。

Decided · 移除 /timeline 路由不再存在
Timeline 现在的核心价值是"你看,我们采到了"——这是工程师说服自己产品在工作的视图,不是用户需要的视图。它的存在还有三个副作用:
  • 稀释了 Ask 的中心地位。用户面对两个 tab 时会犹豫"我应该去哪",但 Corivo 的产品本质就是"提问",不应该有第二个并列的目的地。
  • 把"被监视感"放大了。把所有 frame 一字排开给用户看,无意中强调了"我们记录了你所有屏幕"——这个感受跟"温暖工作伙伴"是冲突的。Frame 应当是 Ask 引用时才浮现的东西,不是浏览的对象。
  • 它需要的功能可以被更好的形态承接。Capture 控制 / 数据查看 / 隐私验证,有更合适的去处(见下表)。

03 · Key Flows

四条主路径。

这四条覆盖了 90% 的使用场景。把它们走顺,产品就站住了。

Flow 01 冷启动 · 第一次问
打开主窗口 → 空状态:还没问过我什么 → 输入栏聚焦 → 问 → 流式回应 + 引用帧
Flow 02 Quick Ask · 问完就走
⌥⌥ 双击 → 浮层 + 当前 focus context → 问 → 回应 → Esc 收回
Flow 03 Quick Ask → 主窗口 · 接续深聊
浮层中已有几轮对话 → 点"在 App 中查看" → 主窗口打开 · 该会话定位 → 继续聊
Flow 04 引用帧 · 看一眼回到对话
读到引用 frame chip → 点击 → 右侧 Drawer 滑出 · 大图 + 文本 → 关掉 → 回到对话原位

06 · Out of Scope

这次 redesign 里不做的事。

明确写出来,避免一边设计一边膨胀。下面这些有道理但不在这次 IA 里——它们要么需要后端配合,要么是后续阶段的事。

不做 · 1
主题切换 · 暗色模式
跟随系统就好。手动切换会让设计 token 翻倍,这次先不做。
不做 · 2
多窗口 / 多账号
单窗口、单账号心智更干净。多窗口需求不强,以后再说。
不做 · 3
导出 / 分享会话
隐私敏感,且现阶段没有对应的产品场景。
不做 · 4
自定义快捷键
⌥⌥ 是核心心智,不应该让用户自定义掉。其他动作走系统默认。
不做 · 5
Frame 全文搜索的独立入口
用户的"搜索"心智应该走 Ask——"我刚才看那个 X 是什么"——而不是去 grep frame。
不做 · 6
Notification overlay 的实际投用
代码里保留,但 v3 redesign 不规划它的产品形态。等真有 proactive 场景再设计。
