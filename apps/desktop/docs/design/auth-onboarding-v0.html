02 · Onboarding · Step 1 of 2 · Permission

第一步 · AX 是主路径,Screen Recording 是兜底。

Corivo 默认通过 macOS 辅助功能(AX Tree)读取屏幕里的字——这是主要路径。屏幕录制是 AX 读不到时的 fallback(转走 OCR)。两个权限都必须授权,但呈现时辅助功能在前、主;屏幕录制在后、备。Trust covenant 仍然前置。

dual-permission-flow Engineering · Required
双权限 · 串行申请流程(Permission 步)
前端 + Tauri command · 走 permission.ax_granted + permission.screen_granted
  1. 用户点击 "好,授权这两个"
  2. 第 1 步:触发 macOS 辅助功能权限对话框 (AXIsProcessTrustedWithOptions)。Permission 卡 #1 状态:等你授权 → 正在等系统确认...
  3. 用户在系统对话框上点 "OK" → 系统跳转到 System Settings → 用户手动开启开关 → 应用通过轮询(每 500ms)检测 → Permission 卡 #1 状态:已授权 ✓
  4. 第 2 步自动触发:屏幕录制权限对话框 (CGRequestScreenCaptureAccess)。Permission 卡 #2 状态:等你授权 → 正在等系统确认...
  5. 同上轮询 → Permission 卡 #2 状态:已授权 ✓
  6. 两个都已授权:稳定 800ms(让用户看到全绿) → 自动跳转 Try-It 步
  7. 边界 · 拒绝任意一个:状态变为 未授权 · 去系统设置 + 旁边出现 "打开系统设置" 按钮(直接 deep link 到对应面板)。轮询继续,授权后自动恢复推进
  8. 边界 · 一次都没弹出:macOS TCC 已记忆该 app 的拒绝,系统不再弹对话框 → 直接走"去系统设置"路径
  9. 不允许跳过:Permission 步没有 next 按钮,只能继续等到两个都绿
quick-ask-first-time Engineering · Required
Quick Ask 的"首次唤起"特殊状态(Try-It 步触发)
前端实现 · 一次性 · 走 Config 标志位 onboarding.first_quick_ask_done
  1. 触发条件:onboarding 在 Try-It 步,用户首次 ⌥⌥
  2. 差异:Quick Ask 浮层入场时,输入框上方多 3 个 suggestion chips:
    1. "我刚才在干什么?"
    2. "解决一下我刚看到的问题"
    3. "把刚才看的内容整理成几条"
  3. chip 行为:点击即填入输入框 + 自动发送(免去用户两步操作)
  4. 结束:用户首次发送后(任意路径),设置 first_quick_ask_done = true,onboarding 窗口同时淡出退场;之后 Quick Ask 不再显示这 3 个 chips
  5. 边界:用户在 Try-It 步直接关 Quick Ask 不发送 → onboarding 窗口仍在,可以再按一次 ⌥⌥;按"finish 按钮 →" → onboarding 直接关闭 + first_quick_ask_done = true
  6. 注意:这 3 个 prompts 都需要真实捕获上下文才能回答——这是 demo 的精髓,不是话术,是产品本身
